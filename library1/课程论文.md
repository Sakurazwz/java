# 图书管理系统的设计与实现

## 摘  要

随着信息技术的快速发展和互联网的广泛普及，传统图书管理方式已难以满足人们对高效、便捷图书服务的需求。本文设计并实现了一套基于 Spring Boot 前后端分离架构的图书管理系统，采用 Java 21 作为后端开发语言，PostgreSQL 作为数据库，React 19 构建前端用户界面。系统实现了图书管理、用户管理、借阅管理、借阅历史查询、馆藏概览等功能模块，并创新性地集成了 Spring AI 框架与本地大语言模型，为用户提供基于馆藏图书的智能推荐服务。系统采用 JWT 无状态认证机制和 BCrypt 密码加密技术保障信息安全，通过基于角色的访问控制（RBAC）实现管理员与普通用户的权限分离。经测试验证，系统功能完善、运行稳定，能够有效提升图书管理效率，改善用户体验，对推动图书管理信息化建设具有一定的参考价值。

**关键词**：图书管理系统；Spring Boot；React；前后端分离；JWT 认证；人工智能

## 第一章 绪论

### 1.1 选题背景

改革开放以来，我国社会经济持续发展，人民生活水平显著提高，社会全面步入小康社会。与此同时，社会形态也在发生深刻转型，生活现代化和劳动社会化特征日益明显。快速的工作节奏和日益提高的生活品质要求，使得人们迫切需要从繁重的工作压力和生活压力中得到解放。在这一背景下，借助信息技术手段提升管理和服务效率，已成为各行业发展的共同趋势。

在图书管理领域，传统手工记录的信息处理方式已暴露出诸多不足。手工登记、人工匹配的方式不仅效率低下、容易出错，还无法满足用户对快速检索、便捷借阅等服务的需求，给工作人员带来了极大困难。这充分说明，传统信息处理模式已经难以适应现代图书管理的要求。随着计算机技术的飞速发展和广泛普及，特别是其在信息资源管理中的深度应用，为图书管理模式的变革提供了坚实的技术基础。计算机技术能够大幅提高工作效率、简化工作流程、改善服务质量，恰好切中图书管理的痛点。将电子信息技术与图书管理相结合，可以实现图书信息一次录入、永久使用、快速匹配用户需求，使用户足不出户即可完成操作，既符合现代生活方式，也推动了图书管理向网络化、智能化方向的深刻变革。

然而，我国图书管理信息化在发展过程中仍面临诸多问题：线上管理系统起步较晚，尽管发展迅速，但从业人员大量涌入，导致管理水平参差不齐，管理体系不规范、不标准；企业规模普遍偏小，难以形成良好的诚信经营形象和品牌影响力；同时，行业监管制度缺失、市场不规范，缺乏对从业人员素质和服务品质的明确衡量标准，导致内部秩序混乱，难以赢得用户的充分信赖。因此，开发一个标准、规范、高效的图书管理系统，以促进图书管理从传统模式向现代化、网络化转型，为管理决策和控制提供有效保障，已成为当前迫切需要解决的问题。

### 1.2 选题意义

**（1）对图书管理行业的意义**  
图书管理系统的建设能够大幅度节省管理成本和人工成本，增强用户信息安全建设，是实现管理现代化的有效途径。系统的应用可以推动行业从粗放型管理向精细化、规范化管理转变，促进图书管理的专业化和网络化，为行业的良性循环发展提供关键支撑。

**（2）对用户的意义**  
高效便捷的图书管理系统不仅丰富了图书管理的服务模式，还可激发整个行业进行自我革新，促使服务专业性和规范性的不断提升。用户可以通过系统快速检索、获取所需图书信息，享受更优质、更透明的服务，真正实现图书资源的便捷共享。

**（3）技术实践意义**  
本系统采用成熟的 Java 技术和 PostgreSQL 数据库进行开发，是计算机技术与传统图书管理行业深度融合的典型案例。系统创新性地集成了 Spring AI 框架与本地大语言模型，实现了基于自然语言交互的智能图书推荐功能。通过系统的设计与实现，可验证主流开发技术在信息管理系统中的适用性和优越性，为类似系统的开发提供参考。

### 1.3 国内外研究现状

国外图书管理信息化起步较早，自 20 世纪 70 年代起，欧美发达国家便开始将计算机技术应用于图书馆管理领域。美国国会图书馆于 1971 年推出的 MARC（Machine-Readable Cataloging）格式，为图书馆自动化管理奠定了基础。进入 21 世纪后，随着云计算、大数据和人工智能技术的兴起，国外图书管理系统逐渐向智能化和个性化方向发展。例如，OCLC 的 WorldCat 全球联合书目系统、Ex Libris 的 Alma 图书馆服务平台等，均采用了先进的云服务和数据分析技术。近年来，ChatGPT 等大语言模型的爆发式增长，为图书推荐、知识问答等功能带来了新的可能性。

国内图书管理信息化虽起步较晚，但发展迅速。从早期的单机版图书管理软件到现在的基于 B/S 架构的图书管理系统，技术水平和应用规模都有了显著提升。目前国内高校和企业开发的图书管理系统多以 Java、PHP 等语言为主，数据库多采用 MySQL 或 PostgreSQL。在 AI 应用方面，国内图书管理系统主要停留在基于规则的推荐算法层面，基于大语言模型的智能推荐功能尚处于探索阶段。

### 1.4 研究内容与方法

本文采用软件工程的标准开发流程，主要研究内容包括：

1. **需求分析**：明确系统的功能需求和非功能需求，梳理用户角色和业务流程。
2. **技术选型**：选择 Spring Boot 3.5、React 19、PostgreSQL 作为核心开发技术栈，选择 Spring AI 框架集成大语言模型。
3. **系统设计**：完成系统架构设计、数据库设计、接口设计和安全设计。
4. **系统实现**：按照分层架构实现后端服务层（Controller、Service、Repository）和前端界面（路由、页面组件、API 调用层）。
5. **系统测试**：对系统进行功能测试和性能测试，验证系统的正确性和稳定性。

研究方法包括文献调研法、案例分析法、结构化系统开发法等。

## 第二章 相关技术介绍

### 2.1 Spring Boot 框架

Spring Boot 是 Pivotal 团队基于 Spring 框架开发的一套快速开发框架，其核心设计理念是"约定优于配置"。Spring Boot 通过自动配置（Auto-Configuration）、起步依赖（Starter Dependencies）和 Actuator 等特性，极大地简化了 Spring 应用的初始搭建和开发过程。

本系统采用 Spring Boot 3.5 版本，该版本基于 Spring Framework 6.x，全面支持 Jakarta EE 规范，要求最低 Java 17 运行环境。系统通过 `spring-boot-starter-web`、`spring-boot-starter-data-jpa`、`spring-boot-starter-security` 等起步依赖快速集成了 Web 服务、数据持久化和安全认证功能。同时，系统采用 `spring-boot-starter-validation` 进行请求参数的声明式校验，通过 `@Valid` 注解配合 JSR-380 规范注解（如 `@NotBlank`、`@NotNull`、`@PositiveOrZero` 等）在 Controller 层实现自动参数校验，显著减少了手动验证代码。

Spring Boot 3.5 还引用了 Spring AI 1.0.0-M6 里程碑版本，为系统集成大语言模型提供了原生支持。

### 2.2 Spring AI 框架

Spring AI 是 Spring 社区推出的面向人工智能应用开发的新一代框架，旨在将 AI 能力无缝集成到 Spring 生态系统中。Spring AI 提供了与多种 AI 模型提供商（如 OpenAI、Azure OpenAI、Ollama 等）的统一抽象接口，开发者可以通过一致的 API 切换不同的 AI 后端。

本系统使用 Spring AI 的 OpenAI Starter（`spring-ai-openai-spring-boot-starter`），通过兼容 OpenAI 接口的协议连接本地 Ollama 服务器上部署的 DeepSeek-R1 模型。Spring AI 的核心组件 `ChatClient` 提供了流式对话接口，通过 Builder 模式可以预设系统提示（System Prompt），实现对话上下文的统一管理。在本系统中，`ChatClient` 被配置为图书管理员角色，能够根据馆藏图书信息为用户提供个性化的阅读推荐。

### 2.3 React 前端框架

React 是由 Facebook（现 Meta）开发并开源的 JavaScript 用户界面库，自 2013 年发布以来已成为全球最流行的前端框架之一。React 采用组件化开发模式，通过虚拟 DOM（Virtual DOM）机制实现高效的界面更新，配合声明式编程范式简化了复杂交互的实现。

本系统前端基于 React 19 版本，使用 Vite 7 作为构建工具，配合 React-Router 7 实现客户端路由跳转。在 UI 组件方面，系统采用 React-Bootstrap 2.10 组件库，提供了导航栏、卡片、表格、模态框等丰富的 UI 控件。前端使用 `localStorage` 存储 JWT 令牌，通过自定义的 `fetchWithAuth` 请求拦截器自动在 HTTP 请求头中附加认证信息，实现了完整的客户端认证流程。

### 2.4 PostgreSQL 数据库

PostgreSQL 是世界上最先进的开源关系型数据库之一，以卓越的稳定性、强大的扩展能力和对 SQL 标准的完整支持而闻名。与 MySQL 相比，PostgreSQL 在复杂查询优化、事务隔离级别、JSON 数据类型支持等方面具有优势。

本系统选择 PostgreSQL 作为数据存储后端，通过 Hibernate 的 `ddl-auto=update` 策略自动创建和更新数据库表结构。系统定义了四张核心数据表：`books`（图书信息）、`users`（用户账户）、`borrow_record`（借阅记录）和 `borrowHistory`（借阅历史）。为提高并发安全性，系统在库存更新操作中使用了 JPA 的 `@Lock(LockModeType.PESSIMISTIC_WRITE)` 悲观写锁机制。

### 2.5 JWT 认证机制

JSON Web Token（JWT）是一种基于 JSON 的开放标准（RFC 7519），用于在网络应用环境间安全地传递声明。JWT 由头部（Header）、载荷（Payload）和签名（Signature）三部分组成，使用点号分隔的 Base64URL 格式编码。

本系统采用 JJWT 0.12.6 库实现 JWT 的生成和验证。JWT 的载荷中包含用户名（`sub`）、用户 ID（`userId`）和角色（`role`）三个字段。系统通过自定义的 `JwtAuthenticationFilter`（继承自 Spring Security 的 `OncePerRequestFilter`）在每个请求中拦截 `Authorization` 头，提取并验证 JWT 令牌，然后动态构建 `UsernamePasswordAuthenticationToken` 并将其设置到 Spring Security 的安全上下文中。系统采用无状态会话策略（`SessionCreationPolicy.STATELESS`），不维护任何服务器端 HTTP 会话。

## 第三章 系统需求分析

### 3.1 功能需求

通过需求调研和用例分析，本系统确定了以下核心功能模块：

**（1）用户管理模块**
- 用户注册：新用户可以通过用户名和密码注册账号，密码长度不少于 6 位。
- 用户登录：已注册用户通过用户名和密码登录系统，系统返回 JWT 令牌。
- 用户信息管理：管理员可以查看所有用户列表、删除用户、修改用户角色（在"管理员"和"普通用户"之间切换）。
- 个人中心：用户可查看自己的基本信息、已借图书数量、未还图书数量和逾期图书数量。

**（2）图书管理模块**
- 图书列表：以卡片或表格两种视图展示所有馆藏图书，包括封面、书名、作者、ISBN、分类、库存数量和已借数量。
- 图书搜索：支持按书名模糊搜索、按 ISBN 精确搜索、按图书分类筛选。
- 图书详情：点击图书卡片可弹出详情窗口，展示图书的完整信息。
- 图书录入：管理员可以添加新图书，包括书名、作者、ISBN、库存数量、分类、封面图片（Base64 编码上传）和简介。
- 图书编辑：管理员可以修改已有图书的信息。
- 图书删除：管理员可以删除未被借出的图书。

**（3）借阅管理模块**
- 借书：用户可以选择图书进行借阅，系统自动将库存数量减 1、已借数量加 1，借阅期限为 90 天。
- 还书：用户归还已借图书，系统自动将库存数量加 1、已借数量减 1。
- 续借：用户可以对已借图书进行续借，归还日期延长 90 天。
- 借阅记录查询：以卡片或表格视图展示当前活跃的借阅记录，支持按书名和用户名筛选。

**（4）借阅历史模块**
- 历史记录查询：记录所有借阅操作（借书、还书、续借）的历史日志。
- 高级筛选：支持按书名、用户名（管理员专属）、日期区间进行多条件组合筛选。

**（5）智能推荐模块**
- AI 图书推荐：基于 Spring AI 框架，将馆藏图书目录作为上下文，通过大语言模型为用户提供自然语言交互的个性化图书推荐。
- 可点击书名：AI 回复中的书名自动转换为可点击链接，点击后跳转到图书管理页面自动搜索。

**（6）馆藏概览模块**
- 数据统计：管理员可以查看馆藏图书总数、借阅中数量和逾期图书数量的实时统计。
- 逾期详情：展示所有逾期图书的详细信息，包括借阅人、借出日期和应还日期。

### 3.2 非功能需求

**（1）安全性**：系统采用 JWT 无状态认证和 BCrypt 密码加密，敏感数据（密码）不在网络传输的 JSON 响应中出现。通过 Spring Security 的 `@PreAuthorize` 注解实现方法级权限控制。

**（2）性能要求**：系统应支持 100 人同时在线访问，页面加载时间不超过 3 秒。借书操作响应时间不超过 1 秒。

**（3）可维护性**：系统采用分层架构（Controller-Service-Repository-DTO），各层职责清晰，代码耦合度低，便于后续扩展和维护。

**（4）可扩展性**：前后端分离架构使得前端和后端可以独立开发和部署，AI 后端可切换为不同的模型提供商而不影响业务逻辑。

### 3.3 用例分析

系统包含两类用户角色：

| 角色 | 权限描述 |
|------|----------|
| 普通用户（USER） | 浏览图书、借书/还书/续借、查看个人借阅记录和历史、使用 AI 推荐 |
| 管理员（ADMIN） | 包含普通用户全部权限，另有：图书增删改、用户管理（查看/删除/角色变更）、查看全部借阅记录、馆藏概览 |

## 第四章 系统设计

```
│  ├─────────┼──────────┼──────────┼────────────┤ │
│  │ Users   │ Overview │ AiRecmd  │  Auth      │ │
│  └─────────┴──────────┴──────────┴────────────┘ │
├─────────────────────────────────────────────────┤
│                    HTTP / JSON                    │
├─────────────────────────────────────────────────┤

│  ┌─────────────────────────────────────────────┐ │
│  │            Controller 层（REST API）          │ │
│  │  BookController / UserController             │ │
│  │  BorrowRecordController / HistoryController  │ │
│  ├─────────────────────────────────────────────┤ │
│  │            Service 层（业务逻辑）               │ │
│  │  BookService / UserService                   │ │

│  ├─────────────────────────────────────────────┤ │

│  ├─────────────────────────────────────────────┤ │
│  │            DTO 层（数据传输对象）                 │ │

│  └─────────────────────────────────────────────┘ │
```

### 4.2 数据库设计

系统使用 PostgreSQL 数据库，通过 Hibernate 的 `ddl-auto=update` 策略自动管理表结构。共设计四张核心数据表：

**（1）books（图书表）**

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGSERIAL | 主键，自增 |
| isbn | VARCHAR(255) | 国际标准书号 |
| title | VARCHAR(255) | 书名 |
| author | VARCHAR(255) | 作者 |
| description | VARCHAR(2000) | 图书简介 |
| cover | TEXT | 封面图片（Base64 编码） |
| category | VARCHAR(255) | 图书分类 |
| count | INT | 库存数量，默认 0 |
| borrow_count | INT | 被借数量，默认 0 |

**（2）users（用户表）**

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGSERIAL | 主键，自增 |
| name | VARCHAR(255) | 用户名，唯一，非空 |
| password | VARCHAR(255) | 密码（BCrypt 加密存储） |
| role | VARCHAR(255) | 用户角色（ADMIN/USER），默认 USER |

**（3）borrow_record（借阅记录表）**

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGSERIAL | 主键，自增 |
| book_id | BIGINT | 关联的图书 ID |
| user_id | BIGINT | 关联的用户 ID |

### 4.4 安全设计

**（1）身份认证**：系统采用基于 JWT 的无状态认证机制。用户登录成功后，后端生成包含用户名、用户 ID 和角色的 JWT 令牌返回给客户端。客户端将该令牌存储在 `localStorage` 中，后续所有请求都在 HTTP 头的 `Authorization: Bearer <token>` 中携带该令牌。

JWT 令牌生成核心代码（`JwtService.java`）：

```java
public String generateToken(String username, Long userId, String role) {
    Date now = new Date();
    Date expiry = new Date(now.getTime() + expirationMillis);
    return Jwts.builder()
            .subject(username)
            .issuedAt(now)
            .expiration(expiry)
            .claims(Map.of("userId", userId, "role", role))
            .signWith(getSigningKey())
            .compact();
}
```

JWT 认证过滤器 `JwtAuthenticationFilter` 在每个请求中提取并验证令牌：

```java
@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {
    @Override
    protected void doFilterInternal(HttpServletRequest request,
            HttpServletResponse response, FilterChain filterChain) {
        String authHeader = request.getHeader(HttpHeaders.AUTHORIZATION);
        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            filterChain.doFilter(request, response);
            return;
        }
        String jwt = authHeader.substring(7);
        try {
            String username = jwtService.extractUsername(jwt);
            if (username != null &&
                    SecurityContextHolder.getContext().getAuthentication() == null) {
                if (jwtService.isTokenValid(jwt, username)) {
                    Claims claims = jwtService.extractAllClaims(jwt);
                    Long userId = claims.get("userId", Long.class);
                    String role = claims.get("role", String.class);
                    UsernamePasswordAuthenticationToken authentication =
                        new UsernamePasswordAuthenticationToken(
                            username, null,
                            List.of(new SimpleGrantedAuthority("ROLE_" + role)));
                    authentication.setDetails(userId);
                    SecurityContextHolder.getContext().setAuthentication(authentication);
                }
            }
        } catch (Exception e) {
            logger.debug("JWT 验证失败: " + e.getMessage());
        }
        filterChain.doFilter(request, response);
    }
}
```

**（2）密码安全**：用户密码采用 BCrypt 算法进行哈希加密后存储。BCrypt 是一种基于 Blowfish 加密算法的密码哈希函数，其最大的特点是内置盐值（Salt）机制且计算速度可配置，能有效抵御彩虹表攻击和暴力破解。

系统通过 Spring Security 的 `PasswordEncoder` Bean 实现密码的加密与验证，注册时使用 `encode()` 加密，登录时使用 `matches()` 比对：

```java
// SecurityConfig 中注册 BCrypt 编码器
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}

// UserService 中注册用户时加密密码
public UserResponse addUser(UserRegisterRequest request) {
    User user = new User();
    user.setName(request.getName());
    user.setPassword(passwordEncoder.encode(request.getPassword())); // BCrypt 加密
    user.setRole("USER");
    return mapper.toUserResponse(userRepository.save(user));
}

// UserService 中登录验证时比对密码
public User authenticate(String name, String password) {
    User user = userRepository.findByName(name)
        .orElseThrow(() -> new EntityNotFoundException("用户名或密码错误"));
    if (!passwordEncoder.matches(password, user.getPassword())) {
        throw new EntityNotFoundException("用户名或密码错误");
    }
    return user;
}
```

**（3）权限控制**：系统采用 RBAC（Role-Based Access Control，基于角色的访问控制）模型，定义 ADMIN 和 USER 两种角色。通过 Spring Security 的 `@PreAuthorize("hasRole('ADMIN')")` 注解在 Controller 层实现方法级的权限控制，管理员专属接口包括图书增删改、用户管理、查看全部借阅记录等。

以图书管理接口为例，增删改操作均需要 ADMIN 角色：

```java
@PreAuthorize("hasRole('ADMIN')")
@PostMapping("/addBook")
public ResponseEntity<BookResponse> addBook(@RequestBody @Valid BookCreateRequest request) {
    BookResponse response = bookService.addBook(request);
    return new ResponseEntity<>(response, HttpStatus.CREATED);
}

@PreAuthorize("hasRole('ADMIN')")
@DeleteMapping("/deleteBook/{id}")
public ResponseEntity<?> deleteBook(@PathVariable Long id) {
    if (borrowService.isBookBorrowedByAnyone(id)) {
        return new ResponseEntity<>(id + "该书已经借出", HttpStatus.NOT_ACCEPTABLE);
    }
    bookService.deleteBook(id);
    return new ResponseEntity<>("bookid为" + id + "已删除", HttpStatus.OK);
}

@PreAuthorize("hasRole('ADMIN')")
@PutMapping("/updateBook")
public BookResponse updateBook(@RequestBody @Valid BookUpdateRequest request) {

}
```

普通用户无需声明 `@PreAuthorize` 注解即可访问（需携带有效 JWT 令牌），例如 `getAllBooks` 和 `getBookById` 接口所有已认证用户均可访问。管理员用户管理接口同样需要 ADMIN 权限：

```java

}

@PreAuthorize("hasRole('ADMIN')")
@PutMapping("/updateRole/{id}")

        @RequestBody Map<String, String> body) {
    String newRole = body.get("role");
    if (!newRole.equals("ADMIN") && !newRole.equals("USER")) {
        return new ResponseEntity<>("角色值无效", HttpStatus.BAD_REQUEST);
    }
    if (SecurityUtils.getCurrentUserId().equals(id)) {
        return new ResponseEntity<>("不能修改自己的角色", HttpStatus.BAD_REQUEST);

    return ResponseEntity.ok(userService.updateRole(id, newRole));
}
```

**（4）数据隔离**：普通用户在操作借阅相关接口时，系统通过 `SecurityUtils` 工具类从 JWT 认证信息中自动获取当前登录用户的 ID：

```java
public class SecurityUtils {
    public static Long getCurrentUserId() {
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();
        if (auth == null || auth.getDetails() == null) {
            throw new IllegalStateException("未获取到当前用户信息");
        }
        return (Long) auth.getDetails();
    }

    public static boolean isAdmin() {
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();
        if (auth == null) return false;
        return auth.getAuthorities().stream()
                .anyMatch(a -> a.getAuthority().equals("ROLE_ADMIN"));
    }
}
```

普通用户调用借阅接口时，`resolveUserId()` 方法忽略请求体中的 `userId`，强制使用 `SecurityUtils.getCurrentUserId()`，防止普通用户越权操作他人借阅记录。

#### 5.1.2 实体模型与 DTO 层

系统定义了四核心 JPA 实体，以 `Book` 实体为例：

```java
@Entity
@Table(name = "books")
@Data
@NoArgsConstructor
@AllArgsConstructor
public class Book {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String isbn;
    private String title;
    private String author;

    @Column(length = 2000)
    private String description;

    @Column(columnDefinition = "TEXT")
    private String cover;    // Base64 编码的封面图片

    private String category; // 图书分类

    @Column(nullable = false)
    private int count = 0;        // 库存数量

    @Column(nullable = false)
    private int borrowCount = 0;  // 被借数量
}
```

在实际开发中，直接将 JPA 实体暴露给前端存在安全隐患（如 `User` 实体包含密码字段）和紧耦合问题。因此系统设计了独立的 DTO（Data Transfer Object）层，将 JPA 实体与 API 传输对象分离，通过 `EntityMapper` 组件实现双向映射。以图书管理为例，系统定义了三种 DTO：

- `BookCreateRequest`：创建图书请求，包含 `@NotBlank` 标题、作者验证注解
- `BookUpdateRequest`：更新图书请求，包含 `@NotNull` ID 和属性验证
- `BookResponse`：图书响应，包含所有展示字段但不包含内部字段

以下为 `EntityMapper` 核心映射代码示例：

```java
@Component
public class EntityMapper {
    // 实体 → 响应 DTO（用于 GET 接口）
    public BookResponse toBookResponse(Book book) {
        BookResponse dto = new BookResponse();
        dto.setId(book.getId());
        dto.setTitle(book.getTitle());
        dto.setAuthor(book.getAuthor());
        dto.setIsbn(book.getIsbn());
        dto.setCategory(book.getCategory());
        dto.setCount(book.getCount());
        dto.setBorrowCount(book.getBorrowCount());
        return dto;
    }

    // 请求 DTO → 实体（用于 POST 接口）
    public Book toEntity(BookCreateRequest request) {
        Book book = new Book();
        book.setTitle(request.getTitle());
        book.setAuthor(request.getAuthor());
        book.setCategory(request.getCategory());
        book.setCount(request.getCount());
        return book;
    }

    // 更新请求 → 更新已有实体（用于 PUT 接口）
    public void updateEntity(Book book, BookUpdateRequest request) {
        book.setTitle(request.getTitle());
        book.setAuthor(request.getAuthor());
        book.setCategory(request.getCategory());
        book.setCount(request.getCount());
    }
}
```

DTO 层的引入解除了数据库模型与 API 契约之间的耦合，使得数据库结构的变更不会直接影响前端，同时也避免了敏感信息（如用户密码）通过 API 响应泄露。

#### 5.1.3 借阅核心业务流程

借书、还书和续借是本系统最核心的业务流程。以借书为例，系统在 `BorrowRecordController` 中实现了完整的事务性操作，其核心代码如下：

```java
@PostMapping("/add")
public ResponseEntity<?> registerBorrow(@RequestBody @Valid BorrowRecordCreateRequest request) {
    Long bookId = request.getBookId();
    Long userId = resolveUserId(request.getUserId());

    if (bookId == null || userId == null) {
        return new ResponseEntity<>("bookId或者userId参数缺失", HttpStatus.BAD_REQUEST);
    }

    // 同一用户不能重复借同一本书
    if (borrowService.hasBorrowedThisBook(bookId, userId)) {
        return new ResponseEntity<>(bookId + "，借书失败，你已借过该书", HttpStatus.CONFLICT);
    }

    LocalDate borrowDate = LocalDate.now();
    LocalDate returnDate = borrowDate.plusDays(90);

    borrowService.addBorrow(bookId, userId, borrowDate, returnDate);
    bookService.borrowBook(bookId);
    borrowHistoryService.addBorrowHistory(bookId, userId, "借书90天");
    return new ResponseEntity<>(userId + "," + bookId + "," + "已借成功", HttpStatus.OK);
}
```

`BookService.borrowBook()` 方法负责库存更新，使用 `@Transactional` 事务注解和 `PESSIMISTIC_WRITE` 悲观写锁保证并发安全：

```java
@Transactional
public Book borrowBook(Long bookId) {
    Book book = bookRepository.findByIdForUpdate(bookId)
        .orElseThrow(() -> new EntityNotFoundException("Book not found with id:" + bookId));
    if (book.getCount() <= 0) {
        throw new IllegalStateException("该书籍库存不足，无法借阅");
    }
    book.setCount(book.getCount() - 1);
    book.setBorrowCount(book.getBorrowCount() + 1);
    return bookRepository.save(book);
}
```

对应的 Repository 层通过 `@Lock(LockModeType.PESSIMISTIC_WRITE)` 注解声明悲观写锁：

在 `BookController.recommend()` 方法中，系统首先从数据库获取全部馆藏图书，将图书的标题、作者、ISBN、库存等信息格式化为结构化文本上下文，然后将用户输入的自然语言需求与馆藏目录一同发送给大语言模型，模型根据馆藏内容生成个性化推荐，确保推荐结果仅来源于实际可借阅的图书。

```java
@GetMapping("/recommend")
public ResponseEntity<Map<String, String>> recommend(@RequestParam String query) {

        .map(b -> "《" + b.getTitle() + "》" + " 作者:" + b.getAuthor()

        .collect(Collectors.joining("\n"));

    String aiResponse = chatClient.prompt()
        .user("以下是图书馆所有馆藏图书：\n" + catalog
                + "\n\n用户需求：" + query.trim()
                + "\n\n请根据馆藏图书为用户推荐合适的书，不要推荐馆藏中没有的书。")
        .call()
        .content();

    return ResponseEntity.ok(Map.of("recommendation", aiResponse));
}
```

```javascript
const fetchWithAuth = async (url, options = {}) => {

        ...options.headers,

        window.location.href = "/login"
        throw new Error("登录已过期，请重新登录")

    return response
}
```

## 总结与展望

本文设计并实现了一套基于 Spring Boot + React 前后端分离架构的图书管理系统，完整覆盖了图书管理、用户管理、借阅管理、借阅历史查询和馆藏概览等核心功能模块。系统采用 JWT 无状态认证、BCrypt 密码加密和基于角色的访问控制（RBAC）保障了系统的安全性；通过 Java 21 的虚拟线程支持和 PostgreSQL 数据库的悲观写锁机制确保了借阅核心业务的高并发场景下的数据一致性。

本系统的主要创新点在于将 Spring AI 框架与本地部署的大语言模型（DeepSeek-R1）相结合，实现了基于馆藏上下文的智能图书推荐功能。用户可以通过自然语言描述阅读偏好，AI 根据实际馆藏图书给出精准的推荐建议，推荐结果中的书名可一键跳转到图书管理页面进行借阅，极大地提升了用户体验和管理效率。

受限于开发时间和个人能力，系统仍存在一些不足和可改进之处：

1. **用户中心功能有待完善**：当前仅展示了已借图书卡片，用户无法直接在个人中心执行借还操作。
2. **缺乏消息通知机制**：系统未实现逾期提醒的主动推送功能（如邮件或站内消息），管理员需手动查看馆藏概览获知逾期情况。
3. **性能优化**：AI 推荐当前为同步阻塞调用，未来可改为异步流式传输（Server-Sent Events）以提升用户体验。

未来可在以下方向进行深入研究和功能扩展：引入 Redis 缓存热门图书和用户会话数据以进一步降低数据库查询压力；对接短信或邮件服务实现逾期自动提醒；将 AI 功能扩展到智能分类、自动摘要等领域；通过 Docker 容器化部署和 CI/CD 流水线实现自动化运维，提升系统的可部署性和可维护性。
